### The core goal of this project
- We are developing the quiet-chatter service.
- This project (`quiet-chatter-docs`) is the documentation repository containing the planning and policies for the service.
- In the parent directory of this workspace, there are sibling directories: `quiet-chatter-front-end` (Frontend) and `quiet-chatter` (Backend).
- The purpose of this project is to clarify requirements and handle the document-based workflow leading up to actual feature implementation.

### [Current Objective]
- Design a daily report system that extracts daily logs from the existing Promtail + Loki + Grafana stack and database, analyzes them using Spring Batch and Gemini AI, and sends a daily summary report to Discord.
- Specific data to collect (Target timeframe: the entire previous calendar day, 00:00 to 23:59):
  - Number of unique IPs connected (using MDC IP logs).
  - Count of 4xx and 5xx error responses per endpoint and HTTP status.
  - Daily Active Users (DAU) based on `memberId` parsed from login logs (e.g., extracting from `Principal: AuthMember[id=...]`).
  - Count of single book views (`/v1/books/{id}`) including the book title (fetched from local DB) and view count.
  - Daily count of reactions (likes, empathy) queried directly from the `reaction` database table.
  - Count of book search keywords (`/v1/books?keyword=...`), decoding the URL to count by keyword.

### [Analysis & Plan]
Based on your final requirements, here is the finalized implementation path for the **Daily Report System Architecture**:

**Proposed Architecture: Dedicated Spring Batch Project (`quiet-chatter-batch`)**
*Reasoning*: We will create an entirely separate repository/project for the Spring Batch application to ensure clear separation of concerns from the main backend. It will handle scheduled log and database data processing.

**Batch Job Steps (Daily Report Job):**
*Execution Time: Daily at 09:00 AM.*
*Data Range: 00:00:00 to 23:59:59 of the previous calendar day.*

1.  **Step 1: Log Data Extraction & Processing (Loki HTTP API)**
    *   **Action**: Query Loki's HTTP API (`/loki/api/v1/query_range`) for the previous calendar day.
    *   **Processing Details**:
        *   *Unique IPs*: Parse MDC IP fields from all incoming request logs to count distinct IPs.
        *   *Errors*: Filter logs for 4xx and 5xx HTTP statuses. Aggregate by endpoint and status code.
        *   *DAU*: Filter for logs containing `Principal: AuthMember[id=`. Extract the `id` value to count distinct active members.
        *   *Book Views*: Filter for request logs to `/v1/books/{id}`. Extract the `{id}` for the next step.
        *   *Searches*: Filter for request logs to `/v1/books?keyword=*`. Extract and URL-decode the keyword, then aggregate counts.

2.  **Step 2: Database Data Extraction (JPA/JDBC)**
    *   **Action**: Query the primary database.
    *   **Processing Details**:
        *   *Reactions*: Query the `reaction` table for entries created during the previous calendar day. Aggregate counts by reaction type (likes, empathy).
        *   *Book Titles (Enrichment)*: Using the book IDs collected in Step 1, query the local database to fetch the corresponding book titles to complete the "Book Views" metric.

3.  **Step 3: Data Aggregation & Formatting**
    *   **Action**: Combine all extracted data (Logs + DB) into a structured Java Object (e.g., `DailyReportData`).
    *   **Formatting**: Transform this object into a clear, multiline string list.
        *   *Example Format*:
            ```text
            - 고유 접속 IP 수: 150
            - DAU (일간 활성 유저): 45
            - 에러 발생 현황: [500] /v1/talks (3건), [400] /v1/auth (12건)
            - 조회수 높은 책: "소년이 온다" (15회), "채식주의자" (8회)
            - 인기 검색어: "김영하" (20회), "한강" (15회)
            - 일간 리액션: 좋아요(30), 공감해요(15)
            ```

4.  **Step 4: AI Briefing Generation (Gemini API Integration)**
    *   **Action**: Call the Google Gemini API (using a client library like Spring AI or direct HTTP calls).
    *   **Prompt**: Pass the formatted string list from Step 3 with a prompt like: *"다음은 서비스의 전일자 지표입니다. 이 데이터를 바탕으로 어제 서비스의 주요 동향, 특이사항(특히 에러 관련), 그리고 긍정적인 지표를 요약하는 3~4줄의 브리핑 리포트를 작성해주세요."*
    *   **Result**: Receive the AI-generated human-readable briefing.

5.  **Step 5: Delivery (Discord Webhook)**
    *   **Action**: Construct the final Discord message payload.
    *   **Structure**:
        ```text
        [Gemini Briefing Text]

        ---
        [Formatted Raw Data List from Step 3]
        ```
    *   Send this payload via HTTP POST to your configured Discord Webhook URL.
